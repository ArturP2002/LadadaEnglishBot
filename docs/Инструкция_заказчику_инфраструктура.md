# Инструкция: подготовка инфраструктуры и доступов

**Документ описывает порядок заказа VPS, домена, DNS и прокси. Результат — готовый набор данных и доступов для дальнейшей настройки сервера.**

---

## 1. Назначение документа

Документ фиксирует шаги по подготовке инфраструктуры и перечень итоговых реквизитов. В объём входят: заказ VPS (Timeweb), покупка домена (reg.ru), DNS для двух поддоменов, покупка прокси (px6.me). Настройка приложений на сервере в этот документ не входит.

---

## 2. Итоговый чеклист: что должно быть готово

Готовые реквизиты и данные:

- VPS Timeweb (РФ): публичный IP, логин `root`, пароль root (из панели Timeweb)
- Домен, купленный на reg.ru
- Две DNS A-записи на IP сервера: `pay.<домен>` и `vk.<домен>`
- Прокси (рекомендуется px6.me): страна **не РФ**; поля: тип (HTTP или SOCKS5), host, port, login, password

---

## 3. Раздел A. VPS Timeweb (Россия)

### Цель

Получить выделенный сервер в РФ и зафиксировать доступы для входа по SSH.

### Рекомендуемые параметры

| Параметр | Значение |
|----------|----------|
| Провайдер | Timeweb Cloud (регион / дата-центр в РФ) |
| vCPU | 2 |
| RAM | 2–4 ГБ (старт: 2 ГБ; запас: 4 ГБ) |
| Диск | SSD 20–40 ГБ |
| ОС | Ubuntu 22.04 LTS или Ubuntu 24.04 LTS |

### Порядок действий

1. Зарегистрировать или войти в аккаунт Timeweb Cloud.
2. Создать облачный сервер (VPS): раздел вроде «Облачные серверы» / «Создать сервер».
3. Выбрать регион в Российской Федерации.
4. Указать параметры из таблицы выше и ОС Ubuntu.
5. При создании сервера выбрать вход по **паролю root** (пароль задаётся или выдаётся панелью Timeweb).
6. Дождаться выдачи сервера.
7. В панели Timeweb зафиксировать:
   - публичный IPv4-адрес;
   - логин: `root`;
   - пароль root (из карточки сервера / раздела доступов Timeweb).

### Итоговые данные (раздел A)

- Публичный IP сервера
- Логин: `root`
- Пароль root
- ОС и тариф (по желанию)

### Ожидаемый результат

SSH-доступ к серверу в РФ под `root` с паролем из Timeweb.

## 4. Раздел B. Домен на reg.ru

### Цель

Иметь один домен второго уровня, на котором будут созданы два поддомена для HTTPS-эндпоинтов (платежи Т‑Банка и Callback VK). HTTPS обязателен для уведомлений банка.

### Порядок действий

1. Открыть [reg.ru](https://www.reg.ru/) и проверить свободность желаемого имени (например, `школа-домен.ru` — здесь и далее условное имя).
2. Купить свободный домен в зоне `.ru` / `.рф` / иной подходящей.
3. Убедиться, что управление DNS доступно в личном кабинете reg.ru (стандартные NS reg.ru или свои — для A-записей достаточно панели DNS reg.ru).
4. Дождаться активации домена (обычно от нескольких минут до нескольких часов).

### Итоговые данные (раздел B)

- Полное имя домена (например, `школа-домен.ru`)
- Подтверждение, что DNS управляется в ЛК reg.ru (или доступ к DNS)

### Ожидаемый результат

Активный домен с возможностью создавать A-записи для поддоменов.

## 5. Раздел C. Два поддомена на одном домене

### Важно

Нужен **один** домен и **два поддомена**, а не два отдельных домена. Оба поддомена указывают на **один и тот же** IP VPS.

| Поддомен | Назначение |
|----------|------------|
| `pay.<домен>` | HTTPS для webhook платежей Telegram-бота и уведомлений Т‑Банка (Notification / Success / Fail) |
| `vk.<домен>` | HTTPS для Callback API сообщества ВКонтакте |

Пример условного домена: `школа-домен.ru`.

- `pay.школа-домен.ru` — платежи и банк
- `vk.школа-домен.ru` — ВКонтакте

### Порядок создания A-записей в DNS reg.ru

1. Войти в личный кабинет reg.ru → домен → управление зоной DNS (или «DNS-серверы и зона»).
2. Добавить запись типа **A**:
   - Имя / хост: `pay`
   - Значение: публичный IPv4 сервера Timeweb
   - TTL: 300–3600 секунд (можно оставить значение по умолчанию)
3. Добавить вторую запись типа **A**:
   - Имя / хост: `vk`
   - Значение: **тот же** IPv4 сервера
   - TTL: аналогично
4. Сохранить изменения.
5. Дождаться распространения DNS (обычно от нескольких минут до 24 часов; чаще — до 1–2 часов).

Не создавать отдельные домены `pay.ru` и `vk.ru`. Не путать A-запись поддомена с записью на корень (`@` / сам домен) — критичны именно `pay` и `vk`.

### Итоговые данные (раздел C)

- Домен
- Подтверждение A-записей `pay` и `vk` → IP

### Ожидаемый результат

Оба FQDN резолвятся в IP VPS.

## 6. Раздел D. Прокси для Telegram Bot API

### Цель

Сервер в РФ часто не имеет стабильного прямого доступа к `api.telegram.org`. Прокси нужен **только** для исходящих запросов Telegram-бота к Telegram API.

Прокси **не** используется для:

- запросов к API Т‑Банка;
- работы VK-бота;
- приёма входящих webhook/notification от банка (они приходят на `pay.<домен>` напрямую).

### Рекомендуемый сервис

Сервис: [https://px6.me/ru/user/proxy](https://px6.me/ru/user/proxy) (личный кабинет прокси px6).

### Обязательное требование по стране

Страна выхода прокси **не должна быть Россией (РФ)**. Выбрать любую другую страну, с которой `api.telegram.org` доступен с российского VPS через этот прокси. Прокси с локацией «Россия» / РФ не подходит.

### Какие поля зафиксировать в ЛК px6

| Поле | Описание |
|------|----------|
| Тип | HTTP или SOCKS5 (как выдан в ЛК) |
| Host | адрес (IP или hostname) прокси |
| Port | порт |
| Login | логин |
| Password | пароль |
| Страна | не РФ (указать выбранную страну) |

Пример записи реквизитов:

```text
socks5://login:password@host:port
```

или

```text
http://login:password@host:port
```

### Порядок действий

1. Зарегистрироваться / войти на https://px6.me/ru/user/proxy.
2. Купить или выделить прокси с выходом **не в РФ**.
3. В карточке прокси зафиксировать: host, port, login, password, тип (HTTP или SOCKS5), страна.

### Ожидаемый результат

Готовые реквизиты прокси (тип, host, port, login, password, страна ≠ РФ) для исходящих запросов только к Telegram API. VK и Т‑Банк работают без этого прокси.
